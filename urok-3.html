Урок 3: HTTP и TCP

HTTP отвечает за то, что сказать (прикладной уровень), а TCP — за то, как гарантированно доставить (транспортный уровень). HTTP работает поверх TCP.

В этом уроке мы разберём, как устанавливается TCP-соединение, как устроены HTTP-запросы и ответы, и что происходит, когда ты вводишь адрес в браузере.

Содержание

Глава 1: TCP — надёжная доставка

TCP (Transmission Control Protocol) — транспортный протокол, который гарантирует доставку. Перед передачей данных устанавливается соединение через тройное рукопожатие (three-way handshake): клиент → сервер: SYN («хочу соединиться»), сервер → клиент: SYN-ACK («ок, я готов»), клиент → сервер: ACK («начинаем»). Только после этого передаются данные.

Ключевые свойства TCP: надёжность (каждый пакет подтверждается, потерялся — переотправка), порядок (данные собираются в правильной последовательности), управление потоком (быстрый отправитель не «затопит» медленного), порты (80 — HTTP, 443 — HTTPS, 22 — SSH).

Аналогия: TCP — телефонный разговор. «Алло? — Алло! — Слышно? — Да», потом говорите; не расслышали — просите повторить.

Глава 2: HTTP — запрос и ответ

HTTP (HyperText Transfer Protocol) — прикладной протокол, работает поверх TCP. Порты: 80 (HTTP) и 443 (HTTPS). Модель «запрос — ответ». Stateless — не помнит предыдущие запросы.

Структура запроса: GET /index.html HTTP/1.1 (метод, путь, версия), затем заголовки (Host, User-Agent), пустая строка и тело (для POST/PUT). Основные методы: GET (получить), POST (отправить), PUT (заменить), PATCH (частично изменить), DELETE (удалить).

Коды статуса: 1xx — информационные, 2xx — успех (200 OK, 201 Created), 3xx — перенаправление (301, 302), 4xx — ошибка клиента (404 Not Found, 403 Forbidden), 5xx — ошибка сервера (500 Internal Server Error).

Глава 3: Как это работает вместе

Что происходит при вводе адреса в браузере:

  1. DNS превращает example.com в IP-адрес.
  2. TCP устанавливает соединение (three-way handshake) на порт 80/443.
  3. Браузер шлёт HTTP-запрос.
  4. Сервер обрабатывает и шлёт HTTP-ответ.
  5. TCP гарантирует целостность и порядок данных.
  6. Соединение закрывается (или переиспользуется — keep-alive).

Версии HTTP: HTTP/1.1 — один запрос на соединение, keep-alive; HTTP/2 — мультиплексирование, параллельные запросы; HTTP/3 — работает поверх UDP (QUIC).
